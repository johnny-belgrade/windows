## Original sites actually inspected
- Web application: **https://awuctl.github.io/mvs/** — HTML title **MVS dump**, workflow **Search Products → Browse Files → Generate summary files**, displays product ID, file name, SHA1, SHA256; allows SHA1 / SHA256 / mixed checksum summary files.
- Maintainer's publicly accessible code: **https://github.com/awuctl/mvs** — author's own README describes it as **"Static web frontend for the SQLite MVS database"**. README explicitly says it **does NOT auto-update** and warns content may quickly become useless; repository includes `mvs.sqlite.gz`, HTML frontend and AGPL-3.0 license. The writer's broad claim "Microsoft Visual Studio/Software Dump" is an approximate conflation: **MVS = My Visual Studio subscriber-download metadata dumps**, not an official Microsoft-hosted authentication/download API. This website is third-party, *not Microsoft's canonical digital signing authority*.
- Microsoft official source of subscription download scope: https://visualstudio.microsoft.com/subscriptions/support/ . MVS site indexed checksums can be useful for matching **original Microsoft-published complete installation ISOs** (when exact release/product/language/architecture/filename match).
- The author warns stale snapshots; Microsoft official original UUP Dump `get.php` UUID/out/SHA1 queue and all frozen signed URLs **remain authoritative to our UUP payload**. An ISO we modify is **not binary-identical** to a Microsoft original, so its SHA is expected to differ from MVS; **NEVER** use a catalog SHA to validate a modified BlueLite ISO or to decide deletable Windows CAB/ESD/FOD dependencies.
- No downloaded original 26300.9818 UUP payload hash has been matched to an MVS catalog entry in this review, and no live database row for BlueLite's build was confirmed. MVS is **auxiliary optional metadata only**, never a mandatory source gate, no network dependency for installer, no automated trust escalation or source replacement.
- Safe use by successors: if exact official original Microsoft ISO needed for baseline comparison, manually select product, use Browse Files and exact filename, compare SHA256 (or SHA1 where the catalog actually provides one), record date/product/filesize/catalog digest provenance, and cross-check against a primary Microsoft source when available. Absence/ambiguity -> NO_MATCH not security/integrity failure of custom UUP. Avoid redistributing `mvs.sqlite.gz` or executing arbitrary MVS-derived scripts by default.
