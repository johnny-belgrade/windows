## 7. PRE_DOWNLOAD vs POST_RECONSTRUCTION vs PRE_ISO vs SECOND-STAGE (canonical)

1. `SOURCE_DISCOVERY`: frozen source UUID/arch/edition/locale/converter version/sha; original and active queue manifests; D6 URL transport rebinding strictly by identical `out + checksum`.
2. `PRE_DOWNLOAD`: only native converter-supported **Store/AppX staging minimization**, 5 mandatory identities plus their resolved manifest/framework closure. Do not delete Windows delta/FoD/SSU/LCU/WinRE reference packages from reconstruction set.
3. `RECONSTRUCTION`: apply selected updates/cleanup according to actual pinned v128m; build the install.wim and its boot.wim in canonical converter flow. `SkipWinRE` is **release-profile choice** whose behavior is checked on converter source; if SkipWinRE=1 no installed offline recovery image in install.wim, expose correct user restoration dependency instead of pretending recovery works.
4. `MAX_PRE` **after reconstruction, before ISO**: same universal 26300.x engine that runs standalone, based on source-local capability/CBS/AppX state and owner predicates. Apply proven GREEN, then proven topology-aware AMBER where predicates match; skip absent.
